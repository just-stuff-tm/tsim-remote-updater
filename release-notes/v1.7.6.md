## Own resets are never reported as Heltec reboots
On Oct 25 a REBOOT text made the T-SIM reset the Heltec. About 6 s later the boot output was accepted as an unexpected reboot "while the T-SIM was awake", and the T-SIM reset its modem (`AT+CFUN`) for nothing.

The 1.7.3–1.7.5 guard compared two readings of the T-SIM's clock, taken when it reset the Heltec and when the boot was handled, and allowed 60 s between them. That clock is never set (it reads 2033) and runs from the ESP32-S3's internal RC oscillator. The guard also measured the 60 s at handling time, not when the boot output arrived. If the clock stepped back, or the T-SIM was busy for over a minute after the reset, the guard silently failed.

1.7.6:
- **Self-reset flag.** When the T-SIM resets the Heltec (REBOOT text or USB, after a Heltec firmware update), it sets a flag timed with `millis()`, not the clock. The first boot it sees afterwards (ROM banner, `rst:`, `Repeater ID`) is marked as the T-SIM's own and dropped at once. It is never queued as a reboot and never triggers modem recovery. The flag clears on that boot, or after 5 min if no boot output shows up.
- The same guard covers the **uptime check** (awake status check-ins and the daylight timer poll) and a relayed console `reboot`, which is still reported as "(console)" with no modem reset.
- The clock-based window stays for the GPIO6 wake across deep sleep. It now also counts a clock that stepped back less than an hour as "own", where it used to fail silently.
- New counter **own resets ignored** (`hwo`) on the Modem watchdog card.

## Reset reason
Every post now carries `rr`, the ESP32 reset reason (`esp_reset_reason()`). The T-SIM tab shows it as **Last reset**: power-on, software restart, deep-sleep wake (normal), and panic/crash, watchdog or brownout, which are highlighted. "Woke by" now also names `3` as **Heltec reboot (GPIO6)**.

## Duplicate texts run once
Identical `STATUS` or `CMD` texts found in one inbox pass run once. All of them are still deleted from the modem first. REBOOT and UPDATE are never merged. A dashboard event says how many were merged.

## Dashboard
- Each text send now writes one activity line. The send log and the activity log share one timestamp, and older pairs less than 2 s apart are merged.
- Last reset row, the GPIO6 wake label and the own-reset counter.

## Unchanged
- No outgoing SMS. The OTA partition layout, TSIMUPDATE with rollback, NVS config and all WDCFG settings are unchanged.
