# tsim-updater 1.7.10

## The text that woke the T-SIM runs this wake

With eDRX on (`WDCFG edrx=1`, especially `edrxv=0101`), a text rings the modem (RI / GPIO3) and the ESP32 wakes, but the message is often not in the modem store yet. 1.7.9 ran one unread check and went back to sleep, so every text wake ran the *previous* text. The one that caused the ring waited until the next wake.

On a **text wake only** (wake code 2, the SMS ring), 1.7.10 keeps the modem up until about **22 seconds after boot** and watches the UART for `+CMTI`. When that URC arrives it reads unread texts (and will run an `UPDATE` if that is the command, same as before). At the end of the window it always does one more unread check. At most three extra inbox passes, then that final check, so it cannot loop.

**Awake-time cost.** Up to about **20 extra seconds** on a short text wake (a CMD that would have slept at 8 s now stays until ~22 s). A STATUS, long CMD, or UPDATE that already ran past 22 s adds **0 s**. GPIO6 and watchdog wakes are unchanged. The modem stays in the same light-wake / `CSCLK` path as 1.7.9; it is not power-cycled for this wait.

**Same-wake `WDCFG`.** If this wake's inbox includes `WDCFG edrx=0` or `psm=0`, 1.7.10 sends that to the modem before sleep. In 1.7.9 the apply often waited until the next wake because the first `lpApply` ran before the command, and the one inside `WDCFG` was skipped while TLS ingest had the UART.

Everything else from 1.7.9 is the same: eDRX/PSM default off, `STATUS AUTO`, `smesh`, GPIO6, the three dashboard Heltec sources (stock MeshCore, custom screen, uploaded `.bin`).

## Dashboard (same tree)

- The watchdog-only Heltec UPDATE backup now outlives the T-SIM's watchdog timer (every good wake restarts that timer). TTL is **max(26 h, watchdog interval + 2 h)**, or **48 h** if the interval is not known, is off (`int=0`), or is not a number. Telemetry `wd_int` wins when it is a number **> 0**, so a dashboard off (`WDCFG int=0`) still gets **26 h** while the firmware keeps reporting `wd_int=1440` (the 24 h timer is never unscheduled).
- If an update text was sent, the T-SIM then reported (heartbeat, status, event, …) but never started the download, the stall line says the text is probably still on the modem and should run on the next wake. When the dashboard watchdog interval is **> 0** (or unknown), that line also says the watchdog backup copy will run it. When the user turned the watchdog **off** (`wdcfg.int_min === 0` or a queued/done `WDCFG int=0`), it says it should run on the T-SIM's next **text** wake and does not promise a backup copy. Retry texts it again. The old "never woke up" line is kept when there was no report after the send.

## Risks

- About 20 s extra awake (and modem idle current) on short text wakes. With eDRX off the extra wait is usually unnecessary but still runs; there is no `WDCFG` key to disable it.
- A very late `+CMTI` (well after 22 s) can still wait until the next wake. The 22 s window is aimed at the store-write after RI, not a full 81.92 s eDRX cycle.
- `lpApply` after the inbox adds a few AT commands only when eDRX/PSM settings actually changed.

## Remote off switch

Turn eDRX (and PSM) off from the dashboard: T-SIM tab › Modem watchdog, untick eDRX / PSM, Save. On 1.7.10 that `WDCFG` is sent to the modem in the same wake that runs it. The late window itself stays on every text wake until you flash other firmware. Roll back with **Update T-SIM firmware** to 1.7.9 (or older) if you need the previous short text wake.

Install from the dashboard with **Update T-SIM firmware**. This note is not a published GitHub release.
