# tsim-updater 1.8.2

## The cell modem stays quiet while the repeater is in download mode

A flash could fail a few seconds after the repeater entered download mode, on the first command of the write. The T-SIM was still sending its "flashing" report over the cell link while the repeater was waiting to be programmed.

- The "Flashing" report is sent before the repeater is put into download mode. The final result still names the chip.
- The cell data session is closed before download mode, and the T-SIM waits a moment so the supply can settle. The result is sent after the repeater is running again.
- A failed flash is tried again from the start, up to two more times, including a failure to enter download mode. The first try may use the faster link. Later tries stay at the normal speed. The repeater is held in reset between tries.
- The activity log lists every try. The update card explains each one. If the flash still fails, the hint follows the last try.

## A text that ran is marked as found

The T-SIM card could say "no new text" on a wake where an update text did run. That happened when the text had been waiting in the inbox, or when the update was still running at the time of the report.

- If a new text is run this wake, the card says a new text was found. A text that already ran, or a duplicate in the same check, does not count.
- The mark is made before the command runs, so a long update still shows it.

## A rolled-back T-SIM update leaves a note

When a T-SIM update does not stay and the previous firmware comes back, the next check-in says so: which slot was dropped, the reset reason the new firmware recorded, and how many times it booted.

Install this firmware on the T-SIM (USB or T-SIM update). The repeater firmware does not need to change for these fixes.
