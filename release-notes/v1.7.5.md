## Daylight uptime check (no wire needed)
The T-SIM now checks every hour, in daylight, whether the Heltec has rebooted, using only the serial link it already uses for the repeater console. A reboot is caught even when the GPIO6 wake and serial-banner detection miss it.

How it works:
- The T-SIM wakes on a timer every **N minutes** (default 60; `WDCFG upoll=<0|15-1440>`, 0 = off).
- It reads the solar input. Below the threshold (default **2.0 V**, `WDCFG usol=<mV>`, 0 = day and night) it's night: it goes straight back to sleep without touching the Heltec.
- It also skips the check when the battery is low (below 3.35 V, or while low-battery protection has repeat off).
- Otherwise it sends the stock MeshCore CLI command **`stats-core`** over serial and reads `uptime_secs` (stock v1.18.0: `{"battery_mv":…,"uptime_secs":…,"errors":…,"queue_len":…}`). The modem stays asleep and nothing goes over LTE.
- It compares the reading with the last one plus the time since then. If the uptime went backwards by more than the tolerance (2 min + 10 % of the gap, for clock drift in deep sleep), the Heltec rebooted. Stock MeshCore's 49.7-day uptime wrap is ignored.
- A reboot found this way is handled like the reboot wake: same limits (60 s apart, 6 per 24 h), then a modem reset (`AT+CFUN`, then PWRKEY), and a heartbeat with reason `heltec-reboot`, source `uptime`. If LTE is down, the report is saved and sent with the next check-in (as in 1.7.4).
- Reboots the T-SIM caused itself (REBOOT, a Heltec update, a console `reboot` it relayed) reset the baseline, so they're never reported as unexpected.
- Watchdog wakes run the same uptime check first. Status check-ins (mesh snapshot) also feed it.
- The timer only shortens the existing sleep timer. It never makes a sleep longer than 24 h or a wake longer than the awake deadline.

**Power:** a daylight check is one timer wake of about 2–3 s (boot, ADC read, one CLI command) at roughly 40–60 mA, about 0.04 mAh. A night skip is about 1 s, about 0.02 mAh. With the default 60 min that's under 1 mAh a day. No LTE.

## Wire self-test (diagnostics)
New counters, sent with every post and shown on the T-SIM tab › Modem watchdog:
- **Serial reply bytes** and **GPIO6 pulses during replies.** Every CLI reply from the Heltec also pulls GPIO6 low through the diode. If replies arrive but GPIO6 counts 0 pulses, the wake wire isn't reaching GPIO6.
- **Unprompted bytes and pulses** while awake (the Heltec only prints by itself when it boots).
- **Last sleep's wake arming:** armed, not armed (GPIO6 low), off or auto-off.

## Unchanged
- The GPIO6 reboot wake (1.7.3), awake serial-banner detection and pending reboot reports (1.7.4), and the watchdog (1.7.1/1.7.2).
- No outgoing SMS. The OTA partition layout, TSIMUPDATE with rollback and NVS config are unchanged. WDCFG from older dashboards still works (no `upoll` = keep the current setting).
