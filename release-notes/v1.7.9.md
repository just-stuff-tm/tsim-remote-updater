# tsim-updater 1.7.9

## Lower modem power, still answer texts

Both new modes default to **off**. Until you turn one on, a 1.7.9 T-SIM behaves like 1.7.8: the modem stays registered in `AT+CSCLK=1` sleep with DTR high, a text pulls DTR low (light wake), and a full modem reset is only the fallback when that light wake fails. The modem is not powered off between wakes, so the ring indicator can still wake the ESP32.

- **eDRX** (dashboard: T-SIM tab › Modem watchdog). Off by default. On sends `AT+CEDRXS=1,4,"0010"` (requested cycle 20.48 s). The cycle can be `0000`–`0101` (5.12 s to 81.92 s) via `edrxv`. Off sends `AT+CEDRXS=0`. Only modes 0 and 1 are used. The network grant is read once with `AT+CEDRXRDP`. If that is rejected or empty, the modem stays on normal idle and the dashboard shows `rej` or `none`. The `+CEDRXP` URC is not used.
- **PSM** stays off unless you turn it on. During PSM the modem cannot receive a text until its next active window, so the ring wake is late and a text sits at the network. On sends `AT+CPSMS=1,,,"00100001","00100010"` (requested periodic TAU 1 hour, active time 2 minutes). Off sends `AT+CPSMS=0`. `AT+CPSMS?` on this modem echoes the request, not the network grant, so the dashboard marks the grant unknown. `AT+MEDCR` is not used.
- Settings are `WDCFG` keys `edrx=0|1`, `edrxv=0000`–`0101`, `psm=0|1`, stored in NVS `tsimwd`. They are sent when the modem is awake and registered, and only again after you change them or after a full modem reset / `AT+CFUN`. A failure does not retry in a loop and does not block sleep.
- **Shorter wakes.** After a STATUS report the T-SIM no longer repeats the same AT diagnostics (signal, network, firmware) before sleeping. A CMD wake still skips those. One unread-SMS check runs before sleep on a text wake, instead of waiting around. Updates, the Heltec serial link, the awake reboot monitor, the GNSS warm window and rollback are unchanged.
- Heartbeats and status posts add `edrx`, `edrx_req`, `edrx_nw`, `psm`, `psm_tau`, `psm_act`, and `awake_ms` (how long the previous wake lasted).

## Less work on each wake

The dashboard still gets every field it already reads. The mesh snapshot on a scheduled check stays on unless you turn it off.

- **Scheduled mesh.** `WDCFG smesh=0|1`, default **1** (same as before). `0` skips the Heltec mesh read on the automatic check only. Request status, and any text that is exactly `STATUS`, still fetches it. The hourly cron sends `STATUS AUTO` only when that T-SIM is already on 1.7.9 or newer. Older firmware still gets `STATUS`, because anything else is ignored. GPIO6 `@TSIM STATUS` and the USB `STATUS` command are unchanged: they post telemetry and do not fetch a mesh snapshot (USB `MESH` still does).
- **Settings cache.** When the cache is on, the T-SIM still reads the repeater on the interval and when you press refresh. It posts that copy when the replies changed, when you asked for a refresh, or when the interval elapsed (so the dashboard time moves). If the clock steps backwards, it reads once and skips the post when the replies match the last good copy, then waits for the interval again. A failed read is still posted and tried again next wake. Parts that did not go out stay in the retry queue; a matching hash never deletes that queue.
- **Shorter bring-up.** A text, GPIO6, or timer wake no longer waits 0.8 s for a USB monitor, and a host that has enumerated USB but is not reading cannot stall each log line. Those wakes also skip dumping the last-update log to USB. A successful SMS light wake does not send `ATE0` / `AT+CMEE=2` a second time. A GPIO6 `STATUS` does not run the extra AT diagnostic pass before the status report, which repeats the same queries.

Needs dashboard support from this same tree. Older dashboards keep sending the previous `WDCFG` line; missing keys leave the stored setting as it is. `smesh` omitted means the mesh snapshot stays on.

Install from the dashboard with **Update T-SIM firmware**.
