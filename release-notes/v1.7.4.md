## Heltec reboot detection while the T-SIM is awake
1.7.3 only noticed a Heltec reboot when it woke the T-SIM from deep sleep through the optional GPIO6 wire. 1.7.4 also notices a reboot that happens while the T-SIM is already awake (during a text wake, a watchdog wake or the console window). No extra wire is needed for this part.

How it works:
- While awake, the T-SIM keeps its serial link to the Heltec (GPIO41, 115200) open and reads every byte. A reboot shows up as boot-only output: the ESP32-S3 ROM banner (`ESP-ROM:esp32s3…`, `rst:0x… ,boot:0x…`, printed at 115200) and stock MeshCore's `Repeater ID: <public key>` line. Normal CLI replies never contain these.
- GPIO6 isn't used while awake, because it pulses on every CLI reply too. It's still the deep-sleep wake, as in 1.7.3.
- On a detected reboot the T-SIM does what a 1.7.3 GPIO6 wake does: it resets its modem (`AT+CFUN=0/1`, then a PWRKEY power-cycle if needed), waits for the network, and posts a heartbeat with reason `heltec-reboot` and source `awake`. The dashboard logs "Heltec reboot detected (while the T-SIM was awake) → Watchdog: modem recovered …".
- A reboot right after a console `reboot` command that the T-SIM relayed itself (within 60 s) is logged as **Heltec reboot detected (console)**. It's still reported, but the modem isn't reset.

## Reboot reports are never lost
After any detected Heltec reboot (awake or GPIO6 wake), the T-SIM waits for the modem to come back (up to 2 more minutes, inside the normal awake deadline) and then reports it. If the report can't go out because LTE is down or the post fails, it's kept as a pending report in NVS: count, time of the last reboot and source. That survives deep sleep and power loss. The next successful post of any kind (heartbeat, status, event) carries it, and the T-SIM clears it once the dashboard accepts it. The dashboard then logs "Heltec reboot detected earlier, reported late (LTE was down): N reboots, last … at HH:MM UTC". A watchdog wake with a pending report always sends a heartbeat, even with heartbeats set to "after recoveries only".

## False-trigger safeguards
- Only boot-only text counts. The echo of a command the T-SIM typed itself is skipped, so a console command containing those words can't trigger it.
- Markers from the same boot (ROM banner, then `Repeater ID` about a second later) count once (20 s window).
- Same limits as 1.7.3: at least 60 s between accepted reboots, at most 6 per 24 h. A Heltec reset the T-SIM did itself (REBOOT, after a Heltec update) is ignored. The Heltec update flasher owns the serial link while it runs, so the monitor is off during updates.
- Ignored at a T-SIM cold start (first 60 s after power-up), when both boards boot together.
- Gated by the same setting: `WDCFG hwake=0|1` (dashboard: T-SIM tab › Modem watchdog › *Heltec reboot wake*). Auto-off after spurious GPIO6 wakes only affects the wire, not serial detection.

## Dashboard
- The Modem watchdog card shows "detected N (while awake M)". New heartbeat fields: `wd.hwa` (awake detections), `src` (`wake` | `awake` | `console`), and `tl.hrp`/`hrpa`/`hrps` (pending report). Older T-SIM firmware is unaffected.

## Bench test
1. Wake the T-SIM (Request status, or STAY on its USB serial monitor) and wait 60 s after it boots.
2. Press the Heltec RST button. The T-SIM logs `Heltec boot output seen while awake (rom)`, then `Heltec reboot detected (awake, …) -> modem recovery`.
3. Send `reboot` from the dashboard console. The log shows `Heltec reboot detected (console)` and the modem isn't reset.
4. With LTE unavailable (antenna off), press Heltec RST while awake. The report stays pending (`Heltec reboot report still pending`) and appears on the dashboard with the next successful check-in.

## Unchanged
- Everything from 1.7.3 (GPIO6 deep-sleep wake, wiring, limits) and 1.7.2 (watchdog command fetch, always-armed timer, awake deadline, restart after repeated modem failures).
- No outgoing SMS. The OTA partition layout, TSIMUPDATE with rollback and NVS config are unchanged.
